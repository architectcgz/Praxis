# 会话、分支、历史按需加载与用量管理方案

## 一、背景与目标

Praxis 采用单窗口前端工作区。前端按 SessionID 管理唯一会话页，后端管理会话实例、分支结构、历史事实和执行生命周期。

本方案统一以下约束：

1. 每个 SessionID 在前端只有一个会话页，界面组件共享该会话页持有的状态。
2. 会话具有唯一根分支，根分支不可删除；其他分支只能从主会话历史中已结束 Run 的末尾分叉。
3. 成功、失败、取消和中断的 Run，只要完成收尾并发布结束节点，都允许作为分叉位置。
4. Entry 是历史树节点，发布后的内容不可变；Entry 不提供独立删除入口，只能随所属分支删除。
5. 分支的父关系由实际分叉节点的归属决定，共享祖先不复制、不改变归属。
6. SQLite 是分支存在性与结构元数据的唯一事实来源；分支内 Entry、Run、Turn 的历史事实保存在所属分支的 JSONL 中。
7. 节点目录、正文位置、Run 展示与用量投影是可重建的派生数据，不成为另一套业务事实来源。
8. 索引完整的正常浏览过程中，未访问分支的正文既不提前读取，也不加载到内存；首次建立索引、增量索引和必要中断收尾按明确范围读取。
9. 历史树按需读取轻量节点，历史正文按目标路径分页读取，已结束子代理的历史在用户选择该子代理后加载。
10. 不保留离开分支后的正文缓存；活跃执行持有的内容及尚未成功持久化的内存事实按自身生命周期保留。
11. Turn 保存单次模型请求用量，Run 累加所属 Turn 的用量；Run 结束结果和累计用量固化到 Run Entry。
12. 分支删除以 SQLite 事务为逻辑提交点，之后物理删除分支目录；删除不隐式级联到子分支。
13. 共享注册表只进行短临界区同步，会话命令、数据快照和同步提交按各自职责协调。

## 二、会话与前端工作区

### 2.1 唯一会话页

前端统一维护以 SessionID 为键的已打开会话集合。

- 重复选择同一 SessionID 复用同一个会话页。
- 会话页持有分支选择、当前历史页、Agent 展示、计时、模型选择、草稿、错误和订阅。
- 切换工作区标签或进入设置不销毁后台会话页，后台输出、队列和执行状态继续更新。
- 多个界面组件引用同一会话状态，不各自建立同一 SessionID 的页面使用期。
- 沿用现有工作区状态、Agent store 和组件生命周期，不额外建立页面引用计数或通用 Store 框架。

### 2.2 后端职责

后端按 SessionID 定位已加载会话实例，不登记前端页面身份。会话实例持有必要的结构状态、配置、模型选择和运行期接纳结果，不要求全部历史正文常驻。

- 会话选择完成分支目录读取、必要索引补齐和中断收尾，再返回选中分支的初始化快照。
- 初始化只加载主会话当前展示所需的最新历史页，不加载其他分支和全部已结束子代理的正文。
- 后续命令使用已加载实例，历史查询按范围读取记录，不重新执行整个会话的恢复流程。
- 首次输入建立会话唯一的写入绑定，后续输入复用该绑定。
- 分支切换、创建和删除由正常生命周期进入允许分支操作的结束状态后发起；当前绑定的执行与待办交接已经结束。
- 分支创建由明确的导航或历史分叉操作发起，不根据其他页面的占用自动创建分支。

### 2.3 关闭与删除的区别

关闭会话：

1. 前端等待该会话的打开请求结束。
2. 按 SessionID 请求停止全部所属执行并清空待办。
3. 后端等待准备、工具调用、子执行和结算退出，再释放会话内存与文件资源。
4. 成功后前端移除会话页和订阅；失败时保留界面并显示错误。

关闭会话不删除 SQLite 业务元数据和分支历史文件，也不影响其他会话。没有写入绑定的纯浏览会话同样执行关闭。

会话删除、分支删除是显式的数据删除操作，与关闭会话分开处理。

### 2.4 未加载、空内容与失败

三种状态必须能够区分：

- 未加载：尚未请求该分支或 Agent 的历史内容。
- 已加载为空：查询成功，目标范围内确实没有可展示记录。
- 加载失败：保留错误，不以空数组冒充成功结果。

沿用现有可选历史字段和加载状态表达这些差异，不构造正文缺失的完整 Entry，也不建立内部延迟加载代理对象。

## 三、Branch 与 Entry 的结构和归属

### 3.1 唯一根与分支树

会话建立唯一根分支，根分支没有父分支和分叉节点。所有后续分支都从已有主会话历史中的 Run 结束节点创建，因此始终属于同一棵分支树。

- 根分支身份由元数据确定，不依赖界面名称推断。
- 根分支在会话存续期间不可通过分支删除入口删除，也就不能删除会话最后一个分支；整个会话删除仍按独立操作处理。
- 非根分支只有在没有子分支时才允许删除。
- 不隐式级联删除子分支。

Entry 通过唯一的 ParentID 连接历史。分支拥有自身新增的 Entry，可以继承父历史，但不复制共享祖先。

```text
父分支 A：A1 → A2 → A3
                 └─ 子分支 B：B1 → B2
                                └─ 子分支 C：C1
```

示例中的 A2、B2 都是已结束 Run 的末尾。B 继承 A 的分叉点及之前的历史，B1、B2 属于 B；C1 属于 C。共享祖先始终保留原有归属。

### 3.2 分支元数据

沿用仓库已有身份和字段语义：

| 字段 | 含义 | 数据性质 |
| --- | --- | --- |
| `ID`、`SessionID` | 分支身份及所属会话 | SQLite 业务元数据 |
| `SourceBranchID` | 实际依赖的父分支；根分支为空 | SQLite 业务元数据 |
| `BaseEntryID` | 实际分叉位置；根分支为空 | SQLite 业务元数据 |
| 名称、创建请求身份、创建时间 | 分支命名、重复请求确认与创建事实 | SQLite 业务元数据 |
| `HeadEntryID` | 本分支当前历史末尾；尚未追加内容时等于分叉点 | 从分叉点与所属历史派生 |
| `UpdatedAt` | 分支最后修改时间；空分支以创建时间为基础 | 从创建及内容提交派生 |

SQLite 中权威分支字段与派生字段的职责必须明确。重建节点索引不能删除或重新推断分支存在性、父关系和分叉位置。

分支修改时间不因浏览、切换标签或读取正文而更新。默认分支选择属于会话元数据，删除分支时与分支目录在同一事务内更新。

### 3.3 真实分叉关系

分支的父关系由实际分叉节点的所属分支决定，不由当前界面选中的分支决定。

- `BaseEntryID` 指向被选择的 Run 结束节点。
- `SourceBranchID` 指向拥有该节点的分支。
- 从继承历史中分叉时，直接建立对实际所属分支的父关系。
- 所有祖先历史依赖都体现在分支父子关系中，不产生绕过父子关系的横向依赖。
- 数据提交、节点索引、分支创建和恢复使用同一归属约定。

例如当前浏览 B，却从继承自 A 的 A2 创建 D，则 D 的父分支是 A，不是 B。

在此约束下，没有子分支意味着没有其他分支依赖该分支独有的 Entry。删除不需要 Entry 引用计数或通用垃圾回收机制。

### 3.4 分叉位置

分叉只允许使用主会话历史中已结束 Run 的末尾节点。

- 成功、失败、取消、中断的 Run 都允许分叉，不按执行结果额外限制。
- Run Entry 表达该 Run 完成收尾后的结束位置。
- Run 发布结束节点前完成必要的工具回执、所属子执行收尾和本次需要提交的其他 Entry。
- 本次产生的上下文摘要属于结束位置之前的历史；结束节点发布后，该 Run 不再追加历史内容。
- 中间消息、工具声明、单条工具回执和摘要节点可以浏览，但不作为分支创建起点。
- 子代理历史与主会话历史独立，子代理的结束节点不作为主分支的分叉位置。

工具调用与回执的正确配对由正常执行和恢复收尾流程保证。历史树不维护独立的工具链闭合标记，也不对每个节点重新扫描整条祖先路径。

## 四、事实来源与物理存储

### 4.1 数据职责

| 数据 | 唯一事实来源 | 查询方式 |
| --- | --- | --- |
| 会话身份、项目归属、标题等元数据 | SQLite | 直接查询元数据 |
| 分支存在性、父关系、分叉点、名称等结构元数据 | SQLite | 直接查询分支目录 |
| 分支内 Entry、Run、Turn 历史事实 | 所属分支的 JSONL | 按位置读取，或从完整记录建立派生投影 |
| 节点预览、正文位置、当前 Head、Run 展示、用量投影 | 从业务事实生成的 SQLite 派生索引 | 轻量查询，可按存活历史重建 |
| 活跃执行、取消句柄、临时输出与未持久化接纳结果 | 会话和运行期对象 | 按实际生命周期访问 |

分支结构只有一份权威表达。日志读取和索引重建不能根据目录存在或历史内容自行创建、收养分支。

### 4.2 按分支归属存储

沿用项目和会话的数据目录归属，分支目录平铺：

```text
projects/<projectID>/sessions/<sessionID>/
└── branches/
    ├── <branchA>/
    │   ├── main.jsonl
    │   └── subagents/
    │       └── <agentID>.jsonl
    └── <branchB>/
        ├── main.jsonl
        └── subagents/
            └── <agentID>.jsonl
```

- 主会话 Entry、主 Run 和所属 Turn 记录写入对应分支的 `main.jsonl`。
- 子代理 Entry、子 Run 和所属 Turn 记录写入同一分支目录下对应的子代理日志。
- 每个分支目录只拥有该分支自己新增的内容。
- 父子关系保存在分支元数据中，不通过目录嵌套表达。
- 存活日志只追加，不原地删除其中某行，不因分支删除重写其他分支日志。
- 分支日志路径根据确定的项目、会话、分支和 Agent 身份构造，不把绝对路径加入业务 Entry。

日志定位包含 BranchID。事件的编解码和归属推进仍由会话业务边界负责，底层文件读写不解释业务载荷。

### 4.3 跨分支历史读取

子分支的第一条新增 Entry，其 ParentID 指向分叉节点。尚未追加内容的子分支 Head 直接指向继承的分叉点。

节点索引记录每个 Entry 的实际所属分支及正文位置，因此一条历史路径可以跨越多个分支文件，而不复制历史内容。

对前述 C 的历史读取范围是：

```text
A1 → A2 → B1 → B2 → C1
```

A3 不属于该路径，不读取其正文。共享祖先只保存一份业务记录，不因多个分支引用而改变所有权。

### 4.4 分支创建提交

在会话命令边界内完成分支创建：

1. 通过现有创建请求身份确认是否已经创建，重复请求复用同一结果。
2. 确认选中的主会话 Run 结束节点，并根据节点实际归属确定父分支。
3. 为新分支建立独立目录和空主日志，不复制祖先正文。
4. 在 SQLite 事务中保存分支结构元数据及初始派生定位，初始 Head 等于分叉点。
5. 事务成功后接纳分支选择结果，首次输入时再建立写入绑定。

数据库提交失败时，不发布新分支；尽力移除本次建立的未登记空目录。清理失败留下的目录不进入分支列表，也不被恢复流程自动收养。

## 五、节点目录、历史树与正文按需加载

### 5.1 节点元数据与完整 Entry

轻量节点回答结构和定位问题，完整 Entry 保存实际内容。二者使用同一个 EntryID，不建立第二套历史身份。

节点目录保存完成当前查询所需的信息：

| 信息 | 用途 |
| --- | --- |
| EntryID、ParentID | 连接历史路径 |
| SessionID、所属 BranchID、AgentID | 确认实际所有权与历史范围 |
| RunID、TurnID | 关联执行结果与逐次用量 |
| Entry 类型、角色、创建时间 | 树展示、正文选择与上下文范围选择 |
| 简短预览、必要的结果摘要 | 不读取正文即可展示节点与分支列表 |
| 所属日志、完整行偏移与长度 | 定位完整记录 |

正文定位属于存储实现，不进入前端协议或完整 Entry 的业务内容。

完整 Entry 包括消息、思考、工具参数、工具回执、推理续传状态、摘要及执行结果的完整载荷。尚未读取正文时，只使用节点元数据，不能把缺失正文当作空内容。

### 5.2 预览与目录维护

- Entry 提交时正文已在内存中，直接生成短预览和必要的展示投影。
- 预览遵循现有短文本展示约定，不保存另一份完整正文。
- 分支列表读取 Head 节点预览，不读取整条分支路径。
- Run 展示从结束结果或其派生投影获取，不为列出 Agent 加载完整历史。
- 首次建立索引时可以读取记录生成预览，正常树查询不重复从正文生成。

### 5.3 各操作的读取范围

| 操作 | 读取范围 |
| --- | --- |
| 会话列表、标题与项目导航 | 会话元数据 |
| 打开会话 | 分支目录、必要恢复状态、选中分支主会话的最新历史页 |
| 分支列表 | 分支元数据及 Head 的轻量预览 |
| 打开历史树 | 轻量节点，不读取正文 |
| 点击分支或历史节点 | 目标历史路径上当前页所需的正文 |
| 向前翻页 | 固定目标路径中尚未加载的更早记录 |
| 列出 Agent | 展示元数据、Run 结果摘要和活跃状态 |
| 选择已结束子代理 | 该子代理当前展示页的正文 |
| 会话累计用量 | 保留 Run 的累计投影，不附带全会话 Turn 明细 |
| 启动模型执行 | 目标上下文实际需要的正文，不依赖界面已加载页 |

### 5.4 历史树

历史树在用户请求时读取节点目录，不在会话初始化时预先保存整棵树到页面状态或会话正文集合中。

- 第一阶段按需返回整棵树的轻量节点，不同时引入子树分页、虚拟树或后台预取机制。
- 树只负责展示历史结构和允许选择的 Run 结束节点。
- 浏览中间节点只读取对应路径，不隐式创建分支。
- 取得节点快照后，在数据锁外组织展示顺序。
- 构建采用一次遍历或等价局部计算，不逐节点重新回溯所有祖先。
- 关闭历史树对话框后释放该次查询结果，不建立树结果缓存。

### 5.5 路径与分页

主会话历史和已结束子代理历史从最新页向前读取，使用稳定 EntryID 作为游标。

分页边界包括：

- 目标 Head：固定本次浏览所使用的历史末尾。
- 向前游标：已经加载范围中最早的 EntryID，下一页不重复包含该节点。
- 页大小：在入口统一确定并校验，不引入单独的分页配置框架。
- 返回记录、是否仍有更早内容及下一游标。

执行中的新增记录由现有事件流程接纳，不能用可变数组下标或偏移页码替代历史身份。刷新最新范围时保留当前分支已经加载的旧页并按 EntryID 合并，不能把固定的最早 N 条误当作完整历史。

后端先批量取得所需路径的轻量元数据，再读取本页正文。路径定位在存储查询边界内完成，避免每个节点产生一次独立前后端请求或数据库往返。

### 5.6 选择、释放与实时输出

- 切换分支后释放旧分支已加载正文、历史浏览结果和对应页面历史状态。
- 再次进入同一分支时重新读取，不保留访问过的分支正文缓存。
- 已结束子代理未被选择时，只保留其展示信息，不主动加载历史。
- 活跃子代理继续接收实时输出；运行结束后，未展示的正文不转成长期缓存。
- 当前展示页、活跃 Run、Loop 和尚未成功持久化的内存记录各自持有必要引用。
- 切换工作区标签或进入设置不等于离开分支，不释放会话页，也不停止后台事件接纳。
- 沿用现有请求代次与归属判断，过期响应不能把已离开的分支正文重新放回页面。

不引入 LRU、TTL、全局正文缓存或为缓存建立的节点引用计数。

### 5.7 模型上下文与执行证据

界面历史、模型上下文和 Run 执行证据使用同一套 Entry 身份，但选择范围由各自职责决定。

- 模型上下文从目标路径最后一条上下文摘要开始，读取该摘要及之后实际进入模型上下文的内容。
- 没有摘要时读取该路径所需的模型历史，不能用界面页大小裁剪模型输入。
- 先从节点元数据确定范围，再读取正文，不先加载全部历史再丢弃摘要之前的内容。
- Run 执行证据只持有该 Run 实际接纳的 Entry。
- 输入去重按稳定 InputEntryID 和创建请求身份定位，不扫描整条分支正文寻找输入。
- Run Entry 不进入模型上下文；原始推理续传等内部内容继续遵守现有 Provider 投影规则。
- 已结束 Agent 的展示统计使用 Run 结果投影，不重新读取整段历史调用内容派生逻辑。

## 六、Run、Turn 与用量管理

### 6.1 历史内容与执行结果

| Entry 语义 | 保存内容 | 是否进入模型上下文 |
| --- | --- | --- |
| 消息、工具调用、工具回执、上下文摘要 | 模型交互所需内容及关联身份 | 按现有上下文规则选择 |
| Run Entry | 一次 Run 的执行结果、结束位置及累计用量 | 否 |

具体类型沿用仓库的业务职责和提交边界，不为名称增加只负责转发的层级。

### 6.2 Turn 明细

一次 Run 可以包含多个 Turn，每个 Turn 对应一次实际模型请求。沿用现有 `ModelRequestRecord` 保存逐 Turn 的状态与用量，TurnID 根据所属 Run 和请求序号生成。

请求类型包括普通模型迭代、上下文摘要和工具风险审核。

- 按实际请求记录，而不是只在正常 Assistant 回答后记录。
- 失败或取消仍保存已经取得的真实用量。
- 未返回用量表示未知，不能当作已知零值，也不根据输出长度推算。
- 输入、输出、缓存读取和缓存写入等分项保留现有含义及已知性。
- Turn 与所属 Run、分支的关系在构造时确定，查询不重新推断。
- 开始与收尾记录按同一 TurnID 更新，不把两种状态算成两次请求。

### 6.3 Run 累计与结束节点

Run 的用量是其所属 Turn 用量的累加。

- 运行中沿用运行记录的 `Progress.Usage` 维护累计值，每个 Turn 收尾时累加一次已知用量。
- Turn 明细与接纳后的 Run 累计使用同一次日志提交。
- 主、子 Run 各自累计自身 Turn，不把子 Run 累计再次加入父 Run。
- Run 结算时将结果、展示所需的执行摘要和累计用量固化到稳定身份的 Run Entry。
- 重复结算不创建第二个结束节点，不重复累加用量。
- 查询 Run 总量直接读取累计值，不重新遍历 Turn 求和。
- 结束后的查询使用 Entry 或其派生投影，不要求可变 Run 对象继续存活。

### 6.4 查询与累计

- Turn 明细沿用 Entry 的 RunID、TurnID 关联查询现有请求用量记录；Entry 本身不重复保存用量。
- 明细查询以本次加载 Entry 涉及的 Turn 为范围，批量取得，不为展示一页历史加载全会话请求明细。
- 会话总量查询返回累计值和必要的已知性信息，不附带全会话 Turn 记录。
- 会话累计对保留的唯一 Run 求和，共享祖先不因出现在多个分支路径而重复计量。
- 同一 Run 的最新持久化投影以替换方式维护，不累加历史快照。
- 运行期或尚未持久化的最新 Run 值替换该 Run 的磁盘投影，不与磁盘中的同一 Run 相加。
- Run 累计与 Turn 明细不能相加。
- 删除分支后同步移除其 Run、Turn 派生数据，后续累计不再包含该分支独有的请求。

## 七、提交、索引与恢复

### 7.1 历史提交

Entry、Run 和 Turn 的历史提交继续遵循先接纳内存、再同步追加日志的规则。

1. 在会话既有同步提交边界确定归属、ParentID、创建时间和必要投影，并接纳内存结果。
2. 向所属分支和 Agent 的日志追加完整记录，取得完整行的偏移与长度。
3. 在 SQLite 事务中更新受影响的节点、Head、Run、Turn 等派生数据，以及该日志的索引进度。
4. 按现有业务提交和通知边界发布结果，不在持有注册表锁或 Run 更新锁时等待存储。

同一会话的追加顺序由统一提交边界保证，不为懒加载另建一套写入队列或后台提交机制。

普通历史追加不额外承诺断电持久化，不自动重试可能已经部分写入的记录。

### 7.2 索引进度

每个主、子代理日志记录已完成索引的连续完整位置。

- 节点及相关投影更新，与索引进度推进处于同一个 SQLite 事务。
- 进度之前的完整记录已经全部反映到派生数据，不能越过失败记录直接推进。
- 索引完整时，正常打开只需确认必要进度，不重新解码全部旧正文。
- 存在尚未索引的尾部时，从已记录位置继续读取并推进投影。
- 新日志或首次建立索引需要从起点读取一次，提取元数据后释放不再需要的正文。
- 索引重建只处理 SQLite 登记的存活分支，不根据文件重新建立分支元数据。

正文定点读取与恢复读取分开。普通读取只访问已经完整写入的记录，不调用会备份和截断尾行的恢复逻辑。

### 7.3 提交失败

| 失败位置 | 内存与持久化语义 | 后续处理 |
| --- | --- | --- |
| 历史日志追加失败 | 已接纳内存事实保留，不能认定日志完全未写入 | 报告错误，不自动重试业务操作 |
| 日志完整追加、索引事务失败 | 日志事实保留，索引进度不推进 | 从既有进度补齐投影，不重新追加同一业务记录 |
| 索引补齐失败 | 不能使用陈旧投影冒充最新磁盘查询 | 明确返回存储错误，保持错误来源可辨 |
| 分支创建事务失败 | 新分支未发布 | 清理本次未登记空目录，不收养遗留目录 |

索引落后在统一存储读取与提交边界处理，不在每个节点内部反复校验、修补或扫描全部日志。

已接纳但尚未成功持久化的内容由当前会话继续持有，不能随普通历史页或分支正文一起释放。这是运行期事实保留，不是访问过的分支缓存；会话关闭后，这些未落盘内容仍可能丢失，沿用现有可靠性约定。

当前会话的历史页、节点和用量查询按业务身份合并最新内存接纳结果与持久化投影，以同一记录的最新接纳值为准，不重复返回或计量。尚未取得有效磁盘位置的 Entry 从内存接纳结果读取，不能写入虚假的正文定位；持久化和投影完成后，可以释放仅为保留未落盘事实而持有的引用。

### 7.4 会话恢复

恢复使用 SQLite 权威分支目录和各存活分支的日志：

1. 读取会话及分支元数据，确认根、父关系和默认选择。
2. 补齐必要的增量索引；首次建立或明确重建时按存活日志生成派生目录。
3. 从执行与工具关联投影定位未结束 Run，以及仍缺必要工具回执的恢复候选。
4. 只读取候选执行所需记录，按现有工具调用身份完成配对。
5. 补写中断回执并通过统一结算入口记录中断结果和 Run 结束节点。
6. 返回选中分支主会话的最新展示页，允许后续操作。

恢复候选不能仅由 Run 是否结束决定；已经保存结束状态、但必要回执和完整结束节点尚未提交的执行，也要完成收尾。恢复使用同一稳定 Run 结果身份，不改写已经发布的 Entry，也不为同一 Run 追加第二个结束节点。

恢复不请求模型、不重新执行工具、不恢复旧审批等待或进程内待办。已结束且无恢复需要的历史正文不因此整体加载。

### 7.5 校验与损坏范围

- 外部身份和分页输入在入口校验一次，内部使用已确定的类型和值。
- 读取到的分支元数据、索引边界和完整载荷分别在对应外部读取入口校验。
- 未访问正文的完整载荷校验延迟到实际读取，正常打开不为了验证所有历史而扫描全部正文。
- 正文读取或解码失败准确报告目标记录错误，不返回空内容，不通过反复扫描其他分支掩盖错误。
- 首次建立索引和必要恢复读取到的损坏记录，在该过程明确报错。
- SQLite 分支结构是业务事实，不能宣称整个数据库都可由 JSONL 重建；结构元数据恢复依赖匹配备份。

## 八、分支删除与物理清理

### 8.1 删除语义

- 根分支在会话存续期间保留，不允许通过分支删除入口删除最后一个分支。
- 存在子分支时拒绝删除，不隐式级联。
- 分支删除发生在正常流程已经结束相关执行、准备、结算和队列交接之后。
- 不为删除增加自动停止执行、等待退出或忙碌后重试的独立流程；执行与删除的互斥由正常生命周期和会话命令边界保证。
- 子分支确认、选择计算和删除提交在同一会话命令边界内完成，不与新建子分支交错。

删除未访问分支不加载其历史正文。删除范围根据明确归属确定，而不是扫描正文或按当前加载内容推断。

### 8.2 删除范围

删除分支时移除：

- 分支结构元数据及其创建请求关联。
- 该分支独有的消息、工具回执、摘要和 Run 结束 Entry。
- 该分支所属主、子 Run 记录及 Turn 请求记录。
- 对应节点、Run、Turn 投影和日志读取进度。
- 对应写入绑定、待办、页面结果和派生请求定位状态。
- 该分支的整个物理目录，包括主日志和子代理日志。

继承的祖先不在该分支目录内，不属于删除范围。其他存活分支日志不重写，正文位置不因本次删除改变。

### 8.3 SQLite 提交点

删除按照以下顺序进行：

1. 确认目标是可删除的非根叶子分支，取得其确定的物理目录定位。
2. 目标为当前分支时，计算后续选中的存活分支。
3. 在同一个 SQLite 事务中移除分支结构和所属派生数据，并更新默认分支选择。
4. 事务成功后更新内存和前端可见的分支集合、选择与绑定状态。
5. 释放对应文件资源，删除该分支目录。
6. 返回已经提交的分支选择结果和物理清理结果。

SQLite 事务是逻辑删除提交点。数据库提交失败时不删除文件，也不发布删除成功的内存状态。

### 8.4 物理清理失败与重复执行

数据库已提交、物理目录清理失败时：

- 分支已经不属于存活分支，不能因清理错误重新发布或恢复它。
- 结果明确区分逻辑删除已提交和物理清理失败，不能使用一个普通失败结果让前端继续引用已删除分支。
- 删除当前分支时，前端接纳已提交的新选择，再展示物理清理错误。
- 可以按同一 SessionID 和 BranchID 再次清理确定的目录；不存在的目录按清理完成处理。
- 重复清理不重新建立分支，不重复计算或扣减用量。
- 不自动建立回收站、后台垃圾回收、目录收养或额外删除状态机。

进程在数据库提交后、文件清理前退出，允许留下未登记目录。重新打开时只以 SQLite 存活分支目录为准，不扫描或恢复该目录。

### 8.5 删除当前分支后的选择

从剩余存活分支中按以下顺序选择：

1. `UpdatedAt` 降序。
2. 时间相同时，BranchID 升序。

选择依据是最后修改时间，不是最近浏览时间或固定父分支。根分支不可删除，正常删除后始终有可选分支。

- 默认选择与分支删除在同一 SQLite 事务内更新。
- 前端释放被删除分支的历史和请求结果，按需加载新选择的最新页。
- 不继续查询被删除分支的节点、执行结果或用量。
- 删除非当前分支时保持当前选择。

## 九、接口与前端接入

接口沿用仓库现有业务入口，按职责调整请求范围和快照，不建立另一套历史或用量查询系统。具体 DTO 名称随实现归属确定。

| 入口 | 目标职责 |
| --- | --- |
| `SelectSession` | 完成必要恢复，返回选中分支、绑定、Agent 展示和主会话最新历史页；branchID 为空时优先绑定分支，否则使用默认选择 |
| `CloseSession` | 停止所属执行、等待收尾、释放会话资源；未加载或已关闭按成功处理 |
| `ListBranches` | 读取 SQLite 分支目录和 Head 预览，不读正文 |
| `GetEntryTree` | 按用户请求返回轻量节点，不返回完整载荷 |
| `GetEntriesAt` | 固定目标 Head，按稳定 EntryID 游标向前分页读取该路径 |
| `ListAgentEntries` | 读取被选择 Agent 的历史页，不随 Agent 列表批量展开所有已结束子代理 |
| `CreateBranch` | 确认主会话 Run 结束节点，根据实际归属建立分支结构与空日志 |
| `SwitchBranch` | 返回目标分支选择和所需最新页，不保留原分支正文缓存 |
| 分支删除入口 | 提交结构删除、更新选择并物理清理，明确提交与清理的分阶段结果 |
| `GetSessionUsageSummary` | 返回会话累计及已知性信息，不附带全部请求明细 |
| 现有 Turn 明细入口 | 按当前加载 Entry 的 RunID、TurnID 范围批量查询已有记录 |
| `CancelTask` | 按会话定位队列并确认绑定身份，只取消尚未领取的输入 |

前端接入要求：

- 会话快照不默认携带全部 Agent 历史；历史缺失表示未加载，不表示空历史。
- 分支切换、Agent 选择和向前翻页使用现有查询 Hook、Agent store 与请求过期保护。
- 事件归属继续以 SessionID、BranchID、AgentID、RunID、TurnID 为准，较早请求不能覆盖当前选择。
- 后台会话继续接纳实时事件，不为响应事件重载整个历史。
- 用量展示只关联已经加载的 Entry 所需明细，会话累计独立读取已有 Run 累计。
- 对外只投影展示所需内容，不公开内部推理续传载荷、日志位置或完整冻结配置。

## 十、锁与同步边界

### 10.1 共享注册表同步

共享注册表由资源拥有者负责同步，只保护登记容器，不串行化不同会话的业务执行。不同 SessionID 使用各自的会话命令锁，不能替代对同一个共享 map 的同步。

注册表同步范围限定为：

- 已加载会话、写入绑定和活动执行等共享定位表的查找、登记、移除及定位快照。
- 按 SessionID 管理的会话命令锁登记，以及持有者、等待者的生命周期计数。

完成定位或登记后立即释放注册表锁，不在持有该锁时执行：

- 会话命令、队列状态交接和分支修改。
- 历史正文读取、索引建立、日志重放和配置加载。
- SQLite 操作、文件读写、目录删除或日志输出。
- Run 快照取得、会话命令锁获取或其他对象的锁等待。
- Hook、模型、工具调用、人工审批或执行退出等待。

### 10.2 会话命令、数据与提交

- 按 SessionID 串行化加载、释放、分支结构修改、删除及调度交接。
- 同一会话的队列入队、领取、完成及与活动执行的状态交接在该会话的命令边界内完成。
- 活动登记覆盖执行准备期，正常生命周期保证历史不会在准备、执行或结算尚未退出时释放。
- 正文读取与分支删除、会话关闭通过会话命令边界协调，读取不持有注册表锁或会话数据锁等待磁盘。
- 会话数据锁只保护内部共享容器修改和快照取得；遍历、排序和展示计算在快照取得后执行。
- 模型和工具运行期间不持续持有会话命令锁。
- 命令锁登记覆盖持有者和等待者，全部退出后回收，不依赖某个已加载实例是否存在。
- 历史追加沿用单一同步提交顺序，分支结构创建、删除以 SQLite 事务为提交点，两类职责不能混淆。

不为历史读取额外引入读者租约、正文引用计数、分片锁或通用并发框架。

### 10.3 计算与跨对象调用

1. 历史树从轻量目录一次构建，正文和分支列表查询不逐节点重算整条路径。
2. 用量和执行列表对局部快照的排序在读锁外执行；索引聚合不持有会话注册表锁。
3. 工具控制锁只保护活跃调用、决定和停止状态，不在该锁内调用需要取得 Run 锁的结果查询。
4. Run 更新取得快照后再保存历史，避免更新回调持锁等待会话提交和磁盘。
5. 配置锁只覆盖与编辑流程保持一致的配置读取，不扩大到其他文件、候选构建和日志输出。
6. 日志定位绑定在会话或对应日志资源生命周期内，不为每次追加反查全部元数据，也不建立全局路径缓存。
7. SQLite 事务只处理必要的元数据和投影更新，不在事务内执行长时间 JSONL 扫描、正文解码或目录删除。

内部构造的数据遵循已有约定。确有错误时修正构造和状态推进，不叠加每节点校验、额外锁或内部监督状态。

## 十一、实施顺序与改动范围

### 11.1 实施依赖

先确定分支归属、Run 结束节点和提交规则，再建立轻量目录与定点读取，随后直接在目标读取结构上实现删除和前端展示。

历史按需加载属于本方案数据访问方式的一部分，不作为独立前置改造，也不等全部依赖全量正文的查询完成后再追加。唯一会话页、关闭生命周期和注册表同步边界可按既有职责独立推进。

### 11.2 分阶段实施

1. **数据与生命周期约定。** 固化唯一根、真实父分支、Run 结束分叉点、Turn 明细、Run 累计以及两类提交规则。
2. **分支结构存储。** 在 SQLite 管理权威分支元数据，落地按分支平铺的主、子代理日志路径和创建提交。
3. **定位读取与派生目录。** 支持追加返回完整行位置、从进度继续读和按位置读；同步节点、Head、Run、Turn 投影及索引进度。
4. **读取与恢复。** 分支列表、树、Agent 展示和会话累计使用轻量数据；正文按路径分页、子代理按需读取；恢复只读取必要候选。
5. **执行接入。** 准入去重定点读取，模型上下文按最后摘要选择范围，Run 证据与结束结果按既有运行边界持有和提交。
6. **分支物理删除。** 直接基于归属目录提交 SQLite 删除并清理整个分支目录，完成部分失败与重复清理语义。
7. **前端与协议。** 调整初始化快照、分页、Agent 选择、Turn 明细范围和正文释放，同步 DTO 与生成绑定。
8. **同步与交付。** 检查共享注册表、会话数据和跨对象调用边界，同步已有架构说明并执行构建、静态检查和人工回归。

### 11.3 现有模块职责

- `core/session`：分支关系、历史归属、接纳结果、结束节点与数据快照约定。
- `core/session/entry`：完整 Entry 和具有独立读取语义的节点信息，不承载文件偏移实现。
- `service/session`：会话选择、元数据与历史访问编排、编解码、索引推进和恢复决策。
- `infra/storage`、`infra/jsonl`：SQLite 事务、分支日志定位、完整记录追加和定位读取。
- `service/agent/run`：输入准入、上下文选择、Run 累计和结果结算；不为展示读取全部历史。
- `service/agent`：从活跃状态和结果投影生成 Agent 展示，不附带正文展开。
- `service/coordinator`：会话命令、绑定、队列和执行生命周期，不扩展为正文缓存管理器。
- Wails bindings 与前端现有 session、workspace、agent 模块：协议投影、按需请求、分页与页面生命周期。

按实际职责扩展已有存储能力边界，不为形式完整增加重复 Repository、通用加载管理器或仅转发的模块。

## 十二、风险、回滚与验证

### 12.1 风险与回滚

- 父关系或节点所有权错误会破坏共享祖先，必须在分支创建与外部恢复入口建立正确关系。
- 分支目录是 SQLite 业务事实，派生索引重建不能覆盖它；备份必须同时包含数据库与对应分支日志。
- 日志完整追加而索引失败属于实际提交窗口，必须通过连续索引进度恢复，不能重复执行模型、工具或重复计量。
- 数据库删除已提交而文件清理失败会留下未登记目录；明确报告并允许定点清理，不恢复为可见分支。
- 普通追加沿用不承诺断电持久化的约定，不能把数据库投影成功解释成所有历史正文已经获得额外持久化保证。
- 未访问正文校验延迟，部分载荷错误可能到首次读取时才暴露，不能继续承诺每次打开完整验证全部正文。
- 首次建立索引仍需读取存活历史一次；按需加载的常规性能验收以索引完整、没有恢复候选为前提。
- 程序、前端、生成绑定和数据格式按匹配版本交付，回滚恢复匹配的程序、数据库与日志备份。
- 不自动迁移真实用户历史，不自动建立存储兼容、后台压缩、回收或修复框架。

### 12.2 构建与静态检查

涉及 Wails 签名或 DTO 变更时，按仓库现有约定重新生成绑定，不手工修改生成文件。随后执行：

```sh
cd backend
go build ./...
go vet ./...
go list ./...
cd ../frontend
npm run check
```

本方案文档更新本身不执行代码生成或应用启动。实施验证不新增或运行自动化测试，不保留测试文件，不自动启动应用或开发服务；如必须启动验证应用，先取得明确授权。

### 12.3 人工回归与读取范围

使用独立数据环境和已有验证应用，重点检查：

- 同一 SessionID 只有一个会话页，切换标签和进入设置不重新加载历史或停止后台输出。
- 会话关闭等待全部执行退出，失败时保留界面，不影响其他会话。
- 一个会话加载、索引处理或关闭等待不持有注册表锁，其他会话可以继续定位和交接命令。
- 索引完整且没有恢复候选时，打开分支不读取其他分支独有正文，初始化不展开已结束子代理历史。
- 分支列表、历史树、Agent 列表和会话总量查询不读取历史正文。
- 点击目标分支只加载当前页及必要祖先内容，不读取不在该路径上的其他分叉内容。
- 向前翻页使用稳定身份，不重复、遗漏或以固定最早记录冒充完整历史。
- 分支切换释放旧正文，再次进入重新读取；工作区标签切换保留当前会话展示页。
- 选择已结束子代理才加载其历史，活跃子代理仍持续接收实时输出。
- 模型上下文从最后摘要选择范围，与界面已经加载的页数无关。
- 只有主会话已结束 Run 的末尾可以分叉，成功、失败、取消和中断结果均可；中间节点仅浏览。
- 从继承历史分叉时，父分支取实际节点所属分支，而不是当前浏览分支。
- 根分支不可删除，有子分支时拒绝删除；叶子分支删除不影响共享祖先。
- 删除未访问分支不加载其正文，物理清理只影响该分支目录，不改变其他日志的位置。
- 删除当前分支按 UpdatedAt 降序、BranchID 升序选择；删除非当前分支不改变当前选择。
- 删除数据库事务失败时文件保留；提交后物理清理失败时分支不复活，重复清理不重复扣减用量。
- 未登记遗留目录不会被恢复流程收养，重建派生索引也不会恢复已删除分支。
- Turn 失败或取消仍保存已知用量，未知分项不展示为已知零值。
- Entry 通过 RunID、TurnID 正确关联当前页用量，Run 累计不因页数、分支引用或快照重放重复计量。
- 日志追加失败的已接纳内容不会因切换分支而提前释放，关闭后的丢失风险符合既有规则。
- 索引追加失败从连续位置补齐，不重新发起业务操作；未访问正文错误在实际读取入口准确报告。
- 未结束及缺回执的恢复候选完整收尾，不重新执行模型或工具；其他已结束历史不整体加载。

按实际验证需要记录正文读取条数、读取字节数、索引补齐范围和失败阶段，使用现有日志关联会话、分支、Run 与 Turn，不为此新增独立性能监控系统。
