# 文档规则

## 目的

本文件定义 WALAgent 长期文档的归属、入口、编辑前阅读和验证规则。

## 核心原则

- `README.md` 负责产品概览和仓库入口，不继续承载完整架构细节。
- `docs/README.md` 是文档导航索引。
- `docs/architecture/` 记录目标架构、模块边界、数据流和长期技术约束；尚未实现的内容必须明确标注为草案。
- `docs/contracts/` 记录稳定的 command、event、IPC 和持久化 schema；当前尚未建立稳定 contract。
- `docs/plan/` 记录阶段性实施计划，不作为当前架构事实源。
- 文档正文默认使用中文；代码标识、命令、路径、包名、API 和协议字段保持原文。

## 编辑前阅读

创建、移动、删除或编辑长期文档前：

1. 先读本文件和 `docs/README.md`。
2. 读取目标区域最近的索引和相关事实源。
3. 用代码、配置、测试或上游依赖源码核对技术结论。
4. 搜索新增、移动、重命名或删除路径的现有引用。

## 路径登记

| 路径 | 类型 | Owner | 允许内容 | 禁止内容 | 编辑前阅读 | 验证方式 |
|---|---|---|---|---|---|---|
| `docs/README.md` | 导航入口 | 项目维护者 | 当前事实源和草案入口 | 重复完整设计正文 | 本文件 | 检查所有已登记链接可达 |
| `docs/architecture/` | 架构 | core / runtime 维护者 | 模块边界、状态机、数据流、运行时约束、ADR 风格决策 | 临时任务记录、未经标注的猜测 | 本文件、`README.md`、相关代码和上游依赖 | 检查范围表、路径引用和状态标记 |
| `docs/contracts/` | Contract | core / IPC 维护者 | command、event、schema、错误码和兼容规则 | UI 草图、实施过程 | 对应 architecture 文档 | schema / 类型检查；未建立前不得声称稳定 |
| `docs/plan/` | 计划 | 当前任务负责人 | 可执行步骤、阶段 gate、验证命令 | 长期架构事实 | 对应 architecture / contract | 完成后核对事实是否已回写 owner 文档 |
| `docs/reviews/` | Review 证据 | reviewer | 绑定 commit 或不可变 artifact 的 review 结果 | 覆盖旧 review 轮次 | 被 review 的事实源 | 标明对象、范围和轮次 |

新增长期路径时，必须在同一次变更中更新本文件和 `docs/README.md` 或最近父级索引。

## 架构文档范围格式

架构文档的“本文档范围”必须使用双栏表格：

```markdown
| 本文档负责 | 本文档不负责（见其他文档） |
|---|---|
| 当前文档覆盖的主题 | 相关主题 → `相对路径` |
```

右列没有对应文档时填 `-`。草案必须在标题后标明状态、依据和未决边界。

## 验证

当前仓库尚无文档一致性脚本。文档变更至少执行：

1. 使用 `rg` 检查新增路径已被索引。
2. 检查 Markdown 相对链接指向存在的文件。
3. 检查架构文档包含状态说明和“本文档范围”双栏表格。
4. 检查 `README.md` 与架构文档没有互相冲突的当前结论。

当文档数量或 contract 数量增加后，再建立机械一致性检查；在此之前不得把人工检查描述为自动验证。
