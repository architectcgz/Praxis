# Praxis

**Praxis**：面向学习者本人的多 Agent 编排桌面应用。用户以 Main Agent 推进任务，通过明确的委派输入与能力授权让上下文隔离的 Subagent 分工协作。

- 技术形态：Go + Wails 3（桌面壳）+ React（前端），本机运行，无远程服务端
- 架构模型：一个 Project 对应一个执行目录，可拥有多个 Session；会话通过 ProjectID 关联项目，工具执行与文件预览以项目目录为边界
- 设计文档：`.architecture/architecture.md` 是目标架构入口

## 构建与验证

### 环境要求

- Go 1.26 或更高版本、Node.js 24 和 npm。
- Wails CLI 与前端 `@wailsio/runtime` 均固定为 `v3.0.0-beta.34`，该版本仍处于 Beta 阶段。
- Windows 需要 WebView2 Runtime；其他平台需安装 [Wails 3 对应的原生构建依赖](https://v3.wails.io/getting-started/installation/)。

安装匹配的 CLI，在仓库根目录执行：

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.34
```

确保 Go 的 `bin` 目录已加入 `PATH`，然后构建：

```sh
cd backend
wails3 build
```

`backend/Taskfile.yml` 依次完成依赖安装、绑定生成、前端构建、资源同步及 Go 生产构建，不启动开发服务。当前平台产物输出至 `backend/bin/`，Windows 为 `praxis.exe`。前端产物由 `frontend/scripts/sync-assets.mjs` 同步至 `backend/frontend/dist/`，再嵌入二进制。Windows 的图标、版本信息和 DPI manifest 一并编入产物；版本信息变更时需同步 `backend/build/config.yml`、`backend/build/windows/info.json` 和 manifest。

### 绑定与静态检查

修改桌面服务签名后，在 `backend/` 重新生成 TypeScript 接口和绑定，不手工修改 `frontend/bindings/`：

```sh
wails3 task bindings
go build ./...
go vet ./...
go list ./...
cd ../frontend
npm run check
```

前端 API 从生成的服务模块调用 Go；事件通过 `@wailsio/runtime` 的 `Events.On` 订阅，从事件的 `data` 读取业务载荷。桌面宿主负责系统目录对话框、业务服务就绪与退出时的资源释放。开发环境配置位于 `backend/build/config.yml`，仅在明确需要启动开发服务时使用 `wails3 task dev`。

### 人工验收与回滚

启动桌面应用后的人工验收应覆盖目录选择、项目和会话查询、模型配置保存、直接输入与 FIFO、审批、Pause/Stop、流式输出、错误提示及退出重启恢复。构建与静态检查不能代替这些桌面交互核验；验证恢复行为时使用独立的操作系统用户或虚拟机，不要覆盖真实用户数据。发布前保留匹配的程序与数据备份，出现异常时一并恢复。

会话加载验收：列表查询不读取会话日志；首次打开会话页时，无论是否指定分支，都须完成日志重放后才显示可操作界面。历史 Entry、Agent 和计时随初始化快照一起返回，模型目录和模型选择在选择成功之后读取。打开 A、B 两个会话页后，确认两边草稿、分支选择和错误相互独立；切到 B 时，A 的后台输出、队列、执行状态和计时继续更新，切回 A 不重新加载快照。日志损坏只使对应会话页初始化失败，其他页面仍可打开。

会话配置验收：打开 A、B 两个会话后保存模型参数、密钥及审批选择，确认两者仍使用已加载配置；在 A 空闲时执行 `/reload`，确认仅 A 更新。A 执行中重载应被拒绝；配置损坏或当前模型无法重新解析时，A 应保留原配置，并能继续使用。重载后的工具禁用状态、Agent 定义及审批模式应在同一会话的所有分支一致生效。

执行通知验收：检查开始、结束、取消和子执行通知，以及会话初始化快照中的当前与最近执行信息，确认只包含声明的展示字段，不包含 `ExecutionRecord`、`SystemPrompt`、完整模型配置或内部进度。前端收到生命周期通知后直接更新状态、失败原因和历史，不额外查询 Agent 或重载整个会话；较早执行的结束通知不能清除较新执行的运行状态。主、子执行的完整事实仍写入所属日志，释放 Run 或重新打开会话后可以查询历史，未结束执行按中断收尾且不重新运行。

## 本地数据目录

数据根目录固定为当前用户主目录下的 `.praxis`，不提供环境变量或应用配置覆盖入口：

```text
.praxis/
├── config/                         配置与 Agent 定义
├── projects/
│   └── <projectID>/
│       ├── project.json            项目身份、名称与目录配置
│       └── sessions/
│           ├── <sessionID>.jsonl    主代理条目、执行事实、模型请求及计时
│           └── <sessionID>/
│               └── subagents/
│                   └── agent-<agentID>.jsonl  子代理条目、执行事实、模型请求及计时
├── sessions.db                     SQLite 会话元数据
├── praxis.log                      应用运行日志
└── incomplete-tail-*               恢复时备份的不完整日志尾行（按需生成）
```

同一用户只允许运行一个 Praxis 实例。应用入口在启动 Wails、初始化数据目录和恢复业务之前获取独占运行权，获取失败直接退出。锁文件位于 `os.UserCacheDir()/praxis/instance.lock`；应用关闭后释放锁，但不删除锁文件。

项目配置以 `projects/<projectID>/project.json` 为唯一来源，直接保存项目身份、名称、目录、状态和时间戳。查询直接读取文件，不维护长期内存副本，不加应用层锁，也不依赖数据库关闭状态；项目列表扫描配置目录，按更新时间倒序、项目 ID 升序排列。保存时通过同目录临时文件写入、同步并完整替换目标文件，失败时返回错误，不发布部分内容。配置缺失的目录不列入项目列表，查询遇到损坏配置明确报错。项目创建由项目服务串行处理，检查项目身份与目录冲突。

例如，Windows 上的 `projects/demo/project.json` 可以保存为以下结构；`Path` 必须是当前平台规范化后的绝对路径，项目 `ID` 必须与目录名一致：

```json
{
  "ID": "demo",
  "Name": "示例项目",
  "Path": "E:\\projects\\demo",
  "State": "active",
  "CreatedAt": "2026-01-01T00:00:00Z",
  "UpdatedAt": "2026-01-01T00:00:00Z"
}
```

会话元数据以 SQLite 为唯一来源，保存 SessionID、ProjectID、标题、状态、会话审批模式及时间戳；列表、标题搜索、重命名和审批模式读写不读取历史 JSONL。SessionID 与 ProjectID 共同确定会话日志路径，不保存绝对路径。主会话入口的 AgentID 由 SessionID 派生，定义固定为 `primary`，会话不保存独立的主 Agent 身份或定义引用。

每个 Session 在没有已加载实例时，通过 `SelectSession` 加载模型目录、Provider 凭据、Agent 定义、工具启停和审批模式，并持有只读配置；同一会话的所有分支、Loop 和子执行使用这份配置。模型能力及默认推理等级只在加载时校验，各个已配置推理等级对应的完整模型配置也在加载时准备好；后续按 Provider、模型和推理等级查找现有选项，等级为空时使用默认选项，不重新校验或覆盖参数。保存配置、切换页面或后续请求都不会隐式刷新已打开实例。配置和模型选择不写入会话日志；最后一个页面正常关闭后随会话内存释放，再次打开时读取最新配置并重新选择模型。

输入 `/reload` 只重新加载当前 Session，不影响其他已打开会话。会话的所有分支和子执行均无活跃执行时才允许重载；存在执行、审核或人工审批等待时返回忙碌错误。全部配置加载和校验成功后整体替换会话配置，并按原模型身份与推理等级查找已准备的配置；原选择不存在或配置非法时保留整份旧配置。需要移除当前模型时，应先切换到其他有效模型，再重载。模型选择只能在当前会话已加载的目录内切换，不会读取尚未重载的编辑配置；Provider 切换的未完成选择只保存在前端，完整模型选定后才提交。

审批模式只分全局与会话两级：全局模式保存在 `config/settings.json`，会话覆盖保存在 SQLite 的 `sessions.approval_mode`；值为 `NULL` 时在加载时继承全局模式。可选 `ask`（询问）、`auto`（模型审核）、`yolo`（跳过审核）或继承全局。输入区保存审批选择只更新持久化覆盖，当前有效模式在显式 `/reload` 成功后才更新；界面区分已保存选择与当前有效模式。禁用的工具始终禁止执行，`yolo` 也不例外。

工具启停保存在 `config/tools.json`，顶层只接受 `tools` 字段。未配置的已注册工具默认启用；禁用的工具不暴露给模型，也不能通过执行入口调用。加载时根据实际注册表校验工具名，配置引用未注册工具时加载失败。例如，禁用 Bash 工具：

```json
{
  "tools": {
    "bash": { "enabled": false }
  }
}
```

每行 JSONL 只保存一个 Event。启动只初始化项目配置目录并打开会话数据库，不预加载会话数据。`ListSessions` 只读取元数据；`CreateSession` 只建立元数据与空日志；`SelectSession` 在没有已加载实例时重放所选会话的 JSONL、构建内存 Entry 并完成中断收尾，再返回包含当前分支 Agent、历史 Entry、待办队列和完整计时记录的会话快照，指定分支与默认分支遵循同一加载流程。Session 业务服务持有实例，Coordinator 按 PageID 登记每个打开页面；同一会话仍有页面使用时复用实例，最后一个页面正常关闭后释放历史、配置、模型选择及相关分支请求缓存，不删除 SQLite 元数据和 JSONL。前端等待选择成功后才读取模型数据并接纳快照中的 Agent 数据；后续查询和命令只操作已加载实例，不触发隐式加载，也不执行单独的日志可用性预检。内存记录先接纳，再同步追加日志；写入错误向调用方返回并由界面提示，不撤销已接纳的内存记录。单个会话加载失败不阻止应用启动、列表查询或选择其他会话。

工作区通过标签页维护已打开会话。每个会话页持有自己的 PageID、写入绑定、分支选择、Agent store、历史、计时、模型选择、输入草稿、错误和事件订阅；PageID 标识本次页面使用期，写入绑定仍在首次提交输入时创建。切换显示或进入设置不销毁页面，也不忽略后台页面的事件。关闭页面需要明确确认，先等待打开请求结束，再停止本页执行并清空待办；没有写入绑定的纯浏览页面也必须通知后端关闭。后端等待本页执行收尾，释放写入绑定和页面登记，最后一个页面关闭时同时释放共享会话内存，成功后前端才销毁页面和订阅。关闭一个页面不停止其他页面的执行，不删除已保存的会话历史；关闭失败时保留页面并展示错误。工具栏刷新只刷新目录和模型配置，初始化失败的页面可以重试加载，不为已加载页面重读历史或计时。

页面生命周期接口：

- `SelectSession(sessionID, branchID, bindingID, pageID)`：`pageID` 是前端为本次页面实例生成的必填 UUID，同一页面重试使用同一个值；`branchID` 和 `bindingID` 可为空，分别表示采用默认分支和尚无写入绑定。登记页面不占用分支写入权。
- `CloseSession(pageID, bindingID)`：`bindingID` 可为空；未知或已关闭的 `pageID` 按成功处理。最后一个页面关闭后释放已加载的会话实例，不因历史写入错误拒绝关闭；其他错误沿用通用错误信封。

Agent 实例由各次 Execution 在创建 Run 时创建并持有，执行结束后随 Run 释放，Session 不维护 Agent 注册表。查询空闲主会话时只从元数据与执行事实投影展示，不创建运行实例。Subagent 的上下文与主代理隔离，所属 Session 持有子代理条目、执行记录、模型请求与计时事实，并保存到独立的子代理日志。子 Run 释放后仍可查询其历史；重新打开会话时重放主、子代理日志并完成中断收尾，不重建旧 Run 或继续旧执行。

Session 业务服务负责执行准入、取得冻结配置、接纳输入，并调用 `core/agent/execution` 构造执行记录与 Run。Run 持有执行状态、进度、上下文和专属 Agent，创建时绑定所属核心 Session；运行期间通过已绑定的 Session 提交事实。Coordinator 持有活跃 Run，负责队列调度、分支占用、启动、取消、审批唤醒、结算编排和释放；Loop 负责完整的模型回合、工具调用和摘要流程。会话标题等业务收尾归 Session 业务服务。

进程内通知表达执行过程中已经确定的事实，前端按展示契约直接更新状态；通知不表示日志已经成功写入。事件信封统一携带 SessionID、AgentID、BranchID、BindingID、ExecutionID 和适用的 TurnID，载荷只包含该事件所需的数据，身份字段从信封读取。生命周期通知及对应前端 DTO 不携带完整 `ExecutionRecord`、可变 Run、冻结系统提示词、完整模型配置或内部进度；这些执行事实由 Session 持有并按业务提交协议持久化。

| 通知 | 载荷与消费语义 |
| --- | --- |
| `execution_started` | 开始时间 `startedAt`；执行身份来自信封，前端据事件种类设置运行状态。 |
| `execution_interrupt_requested` | 控制请求接受时间 `appliedAt`；表达已经接受中断请求，执行仍需完成收尾。 |
| `execution_ended`、`request_canceled` | 结束时间 `endedAt`、执行结果 `outcome`、原因码 `failureCode`、原因说明 `failureMessage`、Agent 展示状态 `state` 及本次执行的完整展示条目 `entries`；原因字段按实际结果提供。 |
| `subagent_started` | 子 Agent 的名称、角色定义、类型、创建时间与执行展示摘要，父 Agent、父 Execution 和工具调用的关联标识，以及初始展示条目；在子 Run 创建并登记后、输出前发送。 |
| `subagent_released` | 通过信封定位释放的子运行实例，清理其临时展示；持久化历史保留在 Session 中。 |

Agent 展示查询及初始化快照中的 `currentExecution`、`latestExecution` 使用相同的执行展示摘要契约，只提供执行 ID、状态、结果、开始与结束时间、原因码和原因说明。`currentExecution` 在没有活跃执行时为空，`latestExecution` 在没有执行记录时为空；前端仅维护摘要和历史，不重建后端执行记录。开始通知设置当前执行，结束通知更新最近执行；清理当前执行和临时输出前按执行 ID 确认归属。终态通知保留本次执行的完整展示条目，以便前端直接合并已接纳的内存结果，包括日志写入失败时保留的结果，不额外查询 Agent 或重载整个会话。

初始化后，页面按 SessionID 和 BranchID 消费事件，队列事件还携带 BindingID。`task_queue_changed` 在入队、领取完成、重试归队和取消后更新队列，`operation_timing` 持续更新计时。Wails 接入按展示契约映射载荷，不直接序列化执行记录，也不重新校验本应用生成的数据结构。

执行流程在各自的明确边界主动调用 event 和 hook：event 提供发布订阅，hook 提供扩展分发和只读观察。通知元数据和载荷由触发流程组装，发布与分发机制不读取 Run、不定位 Session，也不推进执行状态或承担业务提交。Run 负责自身状态行为；Loop 负责模型与工具边界，Session 业务服务负责准入与会话收尾边界，Coordinator 负责运行生命周期边界。必要的核心数据类型引用遵循其语义归属，不为改变依赖箭头复制同形业务模型。

Loop 直接编排模型回合和工具执行，提供上下文构建、模型请求、流式响应处理与摘要生成能力。模型响应中的文本、思考、推理状态和工具调用等内容块随 Assistant Entry 完整记录。正常执行先根据响应准备工具调用，再通过核心 Session 同步记录 Assistant Entry，并将同一引用交给 `Run.Accept`，之后才执行工具；主执行调用 `Session.AppendEntry` 推进当前分支，子执行调用 `Session.AppendSubagentEntry` 写入所属子代理历史和日志，不推进主会话分支 Head。主、子执行均在条目接纳后通知界面。不带工具调用的正常回答同样记录 Assistant Entry，随后结束模型循环。

Loop 在每个工具返回后立即记录其真实回执，再通过 `AfterToolExecution` 发送只读通知。回执正文及身份记录后不再覆盖；通知按注册顺序执行，单个处理器失败不阻断其他处理器，汇总错误只记录日志并继续后续流程，不重试工具。历史保存失败会终止当前执行，已取得真实回执的调用不改写为中断回执，只为尚未取得回执的调用补齐中断结果。工具输出的格式化、截断及必要安全处理应在保存和对外暴露之前完成；Session 回执不承担外部原始响应的完整审计存储。

每次模型请求前，Loop 从 Run 读取基础上下文，并在独立请求副本上执行 `BeforeContextBuild` 和 ContextBuilder 构建模型输入。变换可用于精简工具正文或补充模型可见说明，不修改 Session 历史、Run 执行证据及已接纳 Context；下一轮重新从 Run 读取更新后的基础上下文，处理器应尽量保持确定性。变换失败阻止本次模型请求。工具循环内只在最终模型请求边界注入预算提醒，不压缩或裁剪已接纳的 Entry。完整用户轮次正常完成后，Loop 按需生成并记录覆盖整个 Context 的摘要，再更新 Run Context；摘要失败通过错误和日志路径报告，不改变已经完成的回答。

会话创建、工具执行和文件预览都根据 Session 的 ProjectID 读取项目记录，只有 active 项目可创建新会话或执行目录操作。工具相对路径按 `Project.Path` 解析，文件读取与补丁写入继续校验项目目录边界和符号链接，Bash 的工作目录必须位于项目内，但不提供进程级沙箱隔离。

`storage` 管理项目配置文件、SQLite 会话元数据和历史日志文件读写；日志存储只定位文件并读写完整行，不解释会话事件或载荷。JSONL 事件的编码、解码和事件类型分派由 `service/session` 负责，Event 定义与内存状态推进规则属于 `core/session`。`Store` 在关闭时释放数据库连接；会话元数据仓储通过原子 SQL 更新，不额外加仓储锁。手动改名和自动命名由业务层发起，统一携带读取到的原标题进行原子条件更新；原标题不匹配时返回冲突，不自动重试，且不修改标题或时间戳。自动标题在业务层生成，仅在读取到空标题时尝试写入，已有标题时直接跳过。`core/session.Session` 持有完整会话数据和数据锁，先接纳 Entry、分支、执行记录、用量和耗时到内存，再通过 core 定义的 `EventLog.AppendEvent` 同步追加日志；写入失败保留内存更新，重复 Entry 不重复写入。`service/session` 负责选择时重放、恢复决策、实例登记以及配置和模型选择管理，配置锁只保护配置与选择。注册表锁负责实例加载、登记和移除；已加载实例的数据读写不持有注册表锁，不同会话可以独立执行。

Entry 通过 ID 和 `ParentID` 组成历史树，不保存命名分支身份或条目序号。分支持有独立 Head，多个分支可以共享节点；主会话历史按父节点回溯并反转，Run 按接纳顺序维护引用列表。`entry.appended` 事件通过外层 `branch_id` 标记本次追加的目标命名分支，重放时只推进对应 Head，完整 Entry 位于事件 `payload` 中。模型请求序号和 Task 队列顺序具有独立含义，继续保留。

完整业务记录生成后先更新内存，再立即追加一行 JSONL；不逐 token 写日志，不在每条记录、执行结束或退出时额外 fsync，磁盘刷写交给操作系统，不承诺断电持久化。编码、取消和写入错误均向调用方返回，不回滚内存，也不封锁会话；关闭会话时释放内存实例，未成功写入的内存记录可能随实例释放或进程退出而丢失。同一 Entry 的重复提交不会自动补写日志。追加 I/O 失败可能已经产生部分写入，不能据此认定操作可安全重试。执行终态已在内存接纳时，保存失败只报告错误并正常释放执行占用，不反复重试结算。不支持运行期间从外部修改文件。日志层读取时只交付完整行，不完整尾行先备份再截断；业务重放遇到完整坏行明确报错。

创建会话先建立空 JSONL，再提交 SQLite 元数据；提交失败允许留下未被引用的空文件。创建与删除统一由 Coordinator 接纳并计入关闭等待；创建的存储操作不持有调度锁，创建登记复用注册表锁保护。非空的新会话在正常释放实例时退出空会话清理登记，避免退出时把已释放的历史误判为空。应用退出先拒绝新命令，等待已接纳命令与执行全部退出，再单线程清理本进程新建的空会话并释放实例，最后关闭存储。删除由 Coordinator 确认没有活动执行后进行，以 SQLite 删除为提交点：数据库删除失败直接返回错误，不触碰 JSONL；数据库删除成功后释放页面登记、会话内存和分支请求缓存，并尽力删除 JSONL，清理失败允许留下孤儿文件，不回滚数据库删除。会话目录只由 SQLite 查询，不扫描、收养或重放未被引用的 JSONL。

Session 业务服务在选择时读取主代理及各子代理 JSONL 的完整行，解码并重放 Event，重建 Entry、分支、主子 Execution、用量和耗时数据，并匹配工具调用与回执。日志读完后按调用顺序通过核心 Session 向所属主、子代理历史补齐缺失的 `tool_interrupted` 回执，先更新内存再同步写日志；恢复失败则本次选择失败。旧进程留下的未结束主、子执行保存为 `interrupted`，不创建它们的 Run，不请求模型、不继续执行工具，也不恢复审批等待。新的主 Execution 只由新的用户输入触发，新的子 Execution 由当前活跃执行的委派触发。

会话历史只接受单 Event 结构，无法识别的完整日志行会明确报错，不自动迁移或修补。运行前应备份数据目录；需要回滚时同时恢复匹配的程序和数据备份。
