# Praxis

**Praxis**：面向学习者本人的多 Agent 编排桌面应用。用户以 Main Agent 推进任务，通过明确的委派输入与能力授权让上下文隔离的 Subagent 分工协作。

- 技术形态：Go + Wails 3（桌面壳）+ React（前端），本机运行，无远程服务端
- 架构模型：一个 Project 对应一个执行目录，可拥有多个 Session；会话通过 ProjectID 关联项目，工具执行与文件预览以项目目录为边界
- 会话、分支、历史与用量设计：`.architecture/plan/plan-a.md`

## 构建与验证

### 环境要求

- Go 1.26 或更高版本、Node.js 24 和 npm。
- Wails CLI 与前端 `@wailsio/runtime` 均固定为 `v3.0.0-beta.34`，该版本仍处于 Beta 阶段。
- Windows 需要 WebView2 Runtime；其他平台需安装 [Wails 3 对应的原生构建依赖](https://v3.wails.io/getting-started/installation/)。

安装匹配的 CLI，在仓库根目录执行：

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.34
```

确保 Go 的 `bin` 目录已加入 `PATH`，然后构建：

```sh
cd backend
wails3 build
```

`backend/Taskfile.yml` 依次完成依赖安装、绑定生成、前端构建、资源同步及 Go 生产构建，不启动开发服务。当前平台产物输出至 `backend/bin/`，Windows 为 `praxis.exe`。前端产物由 `frontend/scripts/sync-assets.mjs` 同步至 `backend/frontend/dist/`，再嵌入二进制。Windows 的图标、版本信息和 DPI manifest 一并编入产物；版本信息变更时需同步 `backend/build/config.yml`、`backend/build/windows/info.json` 和 manifest。

### 绑定与静态检查

修改桌面服务签名后，在 `backend/` 重新生成 TypeScript 接口和绑定，不手工修改 `frontend/bindings/`：

```sh
wails3 task bindings
go build ./...
go vet ./...
go list ./...
cd ../frontend
npm run check
```

前端 API 从生成的服务模块调用 Go；事件通过 `@wailsio/runtime` 的 `Events.On` 订阅，从事件的 `data` 读取业务载荷。桌面宿主负责系统目录对话框、业务服务就绪与退出时的资源释放。开发环境配置位于 `backend/build/config.yml`，仅在明确需要启动开发服务时使用 `wails3 task dev`。

### 人工验收与回滚

启动桌面应用后的人工验收应覆盖目录选择、项目和会话查询、模型配置保存、直接输入与 FIFO、审批、Pause/Stop、流式输出、错误提示及退出重启恢复。构建与静态检查不能代替这些桌面交互核验；验证恢复行为时使用独立的操作系统用户或虚拟机，不要覆盖真实用户数据。发布前保留匹配的程序与数据备份，出现异常时一并恢复。

会话加载验收：列表查询不读取日志；索引完整且无恢复候选时，打开会话只读取选中分支主历史的最新页，不展开其他分支或已结束子代理正文。首次建立索引允许读取登记分支的历史一次，之后仅补齐连续索引位置后的完整记录。历史树、分支列表、Agent 展示与会话用量累计只使用轻量投影；选择子代理后才加载其正文。分别验证分页、未加载、成功为空和读取失败；损坏正文在实际读取时明确报错，不返回空数组冒充成功。打开 A、B 两个会话页后，确认草稿、分支选择和错误相互独立，切换标签或进入设置仍持续接纳后台事件，不重新加载会话。

会话配置验收：打开 A、B 两个会话后保存模型参数、密钥及审批选择，确认两者仍使用已加载配置；在 A 空闲时执行 `/reload`，确认仅 A 更新。A 执行中重载应被拒绝；配置损坏或当前模型无法重新解析时，A 应保留原配置，并能继续使用。重载后的工具禁用状态、Agent 定义及审批模式应在同一会话的所有分支一致生效。

执行通知验收：检查开始、结束、取消和子执行通知，以及会话初始化快照中的当前与最近执行信息，确认只包含声明的展示字段，不包含 `ExecutionRecord`、`SystemPrompt`、完整模型配置或内部进度。前端收到生命周期通知后直接更新状态、失败原因和历史，不额外查询 Agent 或重载整个会话；较早执行的结束通知不能清除较新执行的运行状态。主、子执行的完整事实仍写入所属日志，释放 Run 或重新打开会话后可以查询历史，未结束执行按中断收尾且不重新运行。

## 本地数据目录

数据根目录固定为当前用户主目录下的 `.praxis`，不提供环境变量或应用配置覆盖入口：

```text
.praxis/
├── config/                         配置与 Agent 定义
├── projects/
│   └── <projectID>/
│       ├── project.json            项目身份、名称与目录配置
│       └── sessions/
│           └── <sessionID>/
│               └── branches/
│                   └── <branchID>/
│                       ├── main.jsonl          本分支主会话的条目、执行与模型请求
│                       └── subagents/
│                           └── <agentID>.jsonl 本分支子代理的条目、执行与模型请求
├── sessions.db                     SQLite 会话、分支结构、默认选择与可重建历史索引
├── praxis.log                      应用运行日志
└── incomplete-tail-*               恢复时备份的不完整日志尾行（按需生成）
```

同一用户只允许运行一个 Praxis 实例。应用入口在启动 Wails、初始化数据目录和恢复业务之前获取独占运行权，获取失败直接退出。锁文件位于 `os.UserCacheDir()/praxis/instance.lock`；应用关闭后释放锁，但不删除锁文件。

项目配置以 `projects/<projectID>/project.json` 为唯一来源，直接保存项目身份、名称、目录、状态和时间戳。查询直接读取文件，不维护长期内存副本，不加应用层锁，也不依赖数据库关闭状态；项目列表扫描配置目录，按更新时间倒序、项目 ID 升序排列。保存时通过同目录临时文件写入、同步并完整替换目标文件，失败时返回错误，不发布部分内容。配置缺失的目录不列入项目列表，查询遇到损坏配置明确报错。项目创建由项目服务串行处理，检查项目身份与目录冲突。

例如，Windows 上的 `projects/demo/project.json` 可以保存为以下结构；`Path` 必须是当前平台规范化后的绝对路径，项目 `ID` 必须与目录名一致：

```json
{
  "ID": "demo",
  "Name": "示例项目",
  "Path": "E:\\projects\\demo",
  "State": "active",
  "CreatedAt": "2026-01-01T00:00:00Z",
  "UpdatedAt": "2026-01-01T00:00:00Z"
}
```

会话和分支结构以 SQLite 为唯一来源，保存 SessionID、ProjectID、标题、状态、会话审批模式、唯一根分支、默认选择，以及分支名称、创建请求、父分支、分叉点和创建时间。列表、标题搜索、重命名和审批模式读写不读取历史 JSONL；分支 Head 与最后修改时间由创建事实及所属历史派生，浏览和切换不更新分支修改时间。ProjectID、SessionID、BranchID 与 AgentID 共同确定日志路径，不保存绝对路径。主会话入口的 AgentID 由 SessionID 派生，定义固定为 `primary`，会话不保存独立的主 Agent 身份或定义引用。

每个 Session 在没有已加载实例时，通过 `SelectSession` 加载模型目录、Provider 凭据、Agent 定义、工具启停和审批模式，并持有只读配置；同一会话的所有分支、Loop 和子执行使用这份配置。模型能力及默认推理等级只在加载时校验，各个已配置推理等级对应的完整模型配置也在加载时准备好；后续按 Provider、模型和推理等级查找现有选项，等级为空时使用默认选项，不重新校验或覆盖参数。保存配置、切换页面或后续请求都不会隐式刷新已打开实例。配置和模型选择不写入会话日志；关闭会话后随会话内存释放，再次打开时读取最新配置并重新选择模型。

输入 `/reload` 只重新加载当前 Session，不影响其他已打开会话。会话的所有分支和子执行均无活跃执行时才允许重载；存在执行、审核或人工审批等待时返回忙碌错误。全部配置加载和校验成功后整体替换会话配置，并按原模型身份与推理等级查找已准备的配置；原选择不存在或配置非法时保留整份旧配置。需要移除当前模型时，应先切换到其他有效模型，再重载。模型选择只能在当前会话已加载的目录内切换，不会读取尚未重载的编辑配置；Provider 切换的未完成选择只保存在前端，完整模型选定后才提交。

审批模式只分全局与会话两级：全局模式保存在 `config/settings.json`，会话覆盖保存在 SQLite 的 `sessions.approval_mode`；值为 `NULL` 时在加载时继承全局模式。可选 `ask`（询问）、`auto`（模型审核）、`yolo`（跳过审核）或继承全局。输入区保存审批选择只更新持久化覆盖，当前有效模式在显式 `/reload` 成功后才更新；界面区分已保存选择与当前有效模式。禁用的工具始终禁止执行，`yolo` 也不例外。

工具启停保存在 `config/tools.json`，顶层只接受 `tools` 字段。未配置的已注册工具默认启用；禁用的工具不暴露给模型，也不能通过执行入口调用。加载时根据实际注册表校验工具名，配置引用未注册工具时加载失败。例如，禁用 Bash 工具：

```json
{
  "tools": {
    "bash": { "enabled": false }
  }
}
```

每行 JSONL 保存一个 Event。启动只初始化配置与数据库，不预加载会话。`CreateSession` 先建立根分支空日志，再事务保存会话、唯一根与默认选择。`SelectSession` 读取 SQLite 权威分支目录，补齐必要索引并完成候选执行的中断收尾，然后返回当前分支 Agent 展示、待办队列和主会话最新历史页；已结束子代理的历史字段缺失表示尚未加载。Session 只持有结构、执行摘要、配置与未完整落盘的接纳结果，完整正文按 EntryID 定位读取。前端每个 SessionID 只创建一个会话页，模型数据在选择成功后读取；后续查询使用已加载实例，不隐式重复恢复。关闭会话先停止全部执行和清空队列，等待准备、工具、子执行及结算退出，再释放内存，不删除数据库与日志。单个会话加载失败不影响其他会话。

工作区按 SessionID 去重维护已打开会话，同一会话的所有界面组件使用唯一会话页持有的分支选择、Agent store、历史、计时、模型选择、输入草稿、错误和事件订阅。首次提交输入时建立会话唯一的写入绑定与队列，后续输入复用该绑定；切换或创建分支前，当前绑定必须没有活动执行和待办。分支由前端明确的导航或历史分叉操作创建，只允许从主会话已完成收尾的 Run 结束节点分叉，成功、失败、取消和中断结果均可。中间消息、工具回执和摘要仅可浏览，不作为发送消息时的隐式分叉起点。切换显示或进入设置不销毁会话页，也不忽略后台会话的事件。关闭需要明确确认，前端先等待打开请求结束，再按 SessionID 请求关闭；没有写入绑定的纯浏览会话也执行关闭。后端等待该会话的全部执行收尾并释放内存，成功后前端才移除会话页和订阅。关闭一个会话不停止其他会话的执行，不删除已保存的历史；关闭失败时保留会话页并展示错误。工具栏刷新只刷新目录和模型配置，初始化失败可以重试加载，不为已加载会话重读历史或计时。

会话生命周期与队列接口：

- `SelectSession(sessionID, branchID)`：`sessionID` 必填；`branchID` 可为空，已有写入绑定时使用绑定分支，否则采用默认分支。指定分支与现有绑定不一致或绑定正在关闭时返回请求冲突。返回快照包含当前绑定身份与待办；纯浏览不创建绑定。
- `CloseSession(sessionID)`：停止该会话的全部执行，清空队列并等待收尾后释放实例；未加载或已关闭的会话按成功处理。不因已报告的历史写入错误拒绝关闭，其他错误沿用通用错误信封。
- `ListBranches(sessionID)`：返回命名分支及最新条目摘要，分支列表不依赖写入绑定。
- `ListAgentEntries({ sessionId, branchId, agentId, headEntryId, beforeEntryId, limit })`：读取被选择 Agent 的历史页。`headEntryId` 为空时固定当前末尾，`beforeEntryId` 为上一页最早 EntryID，下一页不包含该节点；`limit` 默认 50，范围 1～200。返回 `{ headEntryId, entries, hasMore, nextCursor }`，记录按从早到晚排列。
- `GetEntriesAt({ sessionId, headEntryId, beforeEntryId, limit })`：浏览主会话指定节点的固定祖先路径，分页字段与上项相同；不隐式创建分支。
- `GetEntryTree(sessionID)`：按请求返回主会话轻量节点，关闭对话框后释放结果。
- `DeleteBranch({ sessionId, branchId, targetBranchId, bindingId })`：仅允许删除非根叶子分支。返回已提交的 `branch`、`bindingId` 和 `cleanupError`；清理错误不撤销逻辑删除，前端先接纳新选择，再展示错误。对相同目标再次调用只重试确定目录的清理。
- `GetSessionUsageSummary(sessionID)`：返回唯一保留 Run 的累计及已知性，不附带 Turn 明细。
- `ListSessionUsage({ sessionId, turnIds })`：只批量查询当前加载 Entry 涉及的 Turn，每次最多 2000 个身份。
- `ListToolApprovals(sessionID, branchID, agentID)`：直接查询工具执行器登记的待审批调用，无待审批项时返回空数组；不查询 Run 展示状态。
- `StopAgent({ sessionId, branchId, agentId, runId })`：只中断请求指定的执行，目标不匹配时返回请求冲突；不把目标替换为随后启动的新 Run，也不清空待办。
- `CancelTask({ sessionId, bindingId, taskId })`：三个身份均必填，只取消该会话当前绑定中尚未领取的输入。绑定不匹配、正在关闭或任务已被领取时返回请求冲突，任务不存在时返回未找到；不影响当前执行。

主会话 AgentID 由 SessionID 确定，子代理使用独立身份，其上下文与主会话隔离。角色、名称、状态及最近执行统计由配置与 Run 展示投影提供，不为列出 Agent 展开正文。主、子 Run 都在构造时确定 BranchID，事实写入该分支的主日志或子代理日志。活跃子代理持续接收实时输出，结束后未选中的正文释放；选择已结束子代理才加载历史。Run 释放后仍可按位置查询历史，再次打开会话不重建旧 Run 或继续执行。

执行服务负责准入、取得只读配置、接纳输入，并调用 `core/agent/run` 构造执行记录与 Run。Run 的记录、进度和执行证据只由所属执行路径串行访问，Loop 按轮从 Session 读取历史并构建模型上下文；运行期间通过已绑定的 Session 接纳和提交事实。Agent 展示查询读取会话已接纳的执行记录，不取得可变 Run 的引用。Coordinator 持有活跃 Run，负责队列调度、会话写入绑定、启动、取消、审批唤醒、结算编排和释放；控制接口只修改取消或审批控制状态，不直接修改 RunRecord。

进程内通知表达执行过程中已经确定的事实，前端按展示契约直接更新状态；通知不表示日志已经成功写入。事件信封统一携带 SessionID、AgentID、BranchID、BindingID、RunID 和适用的 TurnID，载荷只包含该事件所需的数据，身份字段从信封读取。生命周期通知及对应前端 DTO 不携带完整 `RunRecord`、可变 Run、冻结系统提示词、完整模型配置或内部进度；这些执行事实由 Session 持有并按业务提交协议持久化。

| 通知 | 载荷与消费语义 |
| --- | --- |
| `run_started` | 执行展示摘要 `run`；执行归属来自信封，前端设置当前执行并保留最近结束结果。 |
| `run_interrupt_requested` | 控制请求接受时间 `appliedAt`；表达已经接受中断请求，执行仍需完成收尾。 |
| `run_ended`、`request_canceled` | 执行展示摘要 `run`、Agent 展示状态 `state` 及本次执行的完整展示条目 `entries`；前端按 RunID 确认结束的目标。 |
| `subagent_started` | 子 Agent 的名称、角色定义、类型、创建时间与执行展示摘要，父 Agent、父 Execution 和工具调用的关联标识，以及初始展示条目；在子 Run 创建并登记后、输出前发送。 |
| `subagent_released` | 通过信封定位释放的子运行实例，清理其临时展示；持久化历史保留在 Session 中。 |

Agent 展示查询、初始化快照与生命周期事件共用 `core/agent/run.Snapshot`，只提供执行 ID、状态、结果、开始与结束时间、原因码和原因说明。`currentRun` 在没有活跃执行时为空，`latestRun` 表达最近结束的执行，没有结束结果时为空；前端仅维护摘要和历史，不重建后端执行记录。开始通知设置当前执行，结束通知更新最近结束结果；清理当前执行和临时输出前按执行 ID 确认归属。终态通知保留本次执行的完整展示条目，以便前端直接合并已接纳的内存结果，包括日志写入失败时保留的结果，不额外查询 Agent 或重载整个会话。

初始化后，页面按 SessionID 和 BranchID 消费事件，队列事件还携带 BindingID。`task_queue_changed` 在入队、领取完成、重试归队和取消后更新队列；模型请求、工具事件和历史 Entry 携带对应计时。Wails 接入按展示契约映射载荷，不直接序列化执行记录，也不重新校验本应用生成的数据结构。

执行流程在各自的明确边界主动调用 event 和 hook：event 提供发布订阅，hook 提供扩展分发和只读观察。通知元数据和载荷由触发流程组装，Emitter 及事件分发过程不读取 Run、不定位 Session，也不推进执行状态或承担业务提交。Run 负责自身状态行为；Loop 负责模型与工具边界，Session 业务服务负责准入与会话收尾边界，Coordinator 负责运行生命周期边界。必要的核心数据类型引用遵循其语义归属，不为改变依赖箭头复制同形业务模型。

Loop 直接编排模型回合和工具执行，提供上下文构建、模型请求、流式响应处理与摘要生成能力。模型响应中的文本、思考、推理状态和工具调用等内容块随 Assistant Entry 完整记录。正常执行先根据响应准备工具调用，再通过核心 Session 同步记录 Assistant Entry，并将同一引用交给 `Run.Accept`，之后才执行工具；主执行调用 `Session.AppendEntry` 推进当前分支，子执行调用 `Session.AppendSubagentEntry` 写入所属子代理历史和日志，不推进主会话分支 Head。主、子执行均在条目接纳后通知界面。不带工具调用的正常回答同样记录 Assistant Entry，随后结束模型循环。

Loop 在每个工具返回后立即记录其真实回执，再通过 `AfterToolExecution` 发送只读通知。回执正文及身份记录后不再覆盖；通知按注册顺序执行，单个处理器失败不阻断其他处理器，汇总错误只记录日志并继续后续流程，不重试工具。历史保存失败会终止当前执行，已取得真实回执的调用不改写为中断回执，只为尚未取得回执的调用补齐中断结果。工具输出的格式化、截断及必要安全处理应在保存和对外暴露之前完成；Session 回执不承担外部原始响应的完整审计存储。

每次模型请求前，Loop 直接接收 Session 已接纳的用户输入 Entry 指针，并从绑定分支或子 Agent 读取有序历史；系统提示词属于本次执行的冻结参数。`BuildContext` 只选择最近摘要、保留原文及后续历史中的模型可见条目，`ModelContext.Entries` 与 Session 共享只读 Entry 指针，不批量复制条目，不进行工具配对重排，也不设置请求态保护字段。`AfterContextBuild` 只读观察构建结果，观察失败只记录日志，不改写正文或阻断模型请求；上下文不提供返回替代正文的 Hook。展示性思考块保存在历史中，由 Provider 编码时跳过，不通过改写 Entry 删除。

上下文构建不执行容量检查或压缩；构建完成后，Loop 单独评估历史正文、系统提示词、工具定义和输出预留的预算，达到窗口九成时按需压缩较早历史。当前用户输入通过同一 Entry 指针识别，与最近一组工具声明及全部回执一起保留原文，其他较早内容合成为摘要。摘要预算先扣除必留原文和请求开销，保留部分已超限时明确返回资源上限错误，不通过压缩必留原文规避限制。摘要作为新 Entry 通过统一入口提交 Session，并记录保留条目的 `RetainedEntryIDs`；后续轮次只引用这些原文，不重复复制或接纳。摘要生成或提交失败会阻止本次常规模型请求，不重新执行已有副作用的工具。Provider 在完整请求编码后执行最终本地容量检查；预算仍接近上限时仅在待发送请求中注入收尾提醒。已有最终回答的执行直接结算，不再发起模型或摘要请求。

会话创建、工具执行和文件预览都根据 Session 的 ProjectID 读取项目记录，只有 active 项目可创建新会话或执行目录操作。工具相对路径按 `Project.Path` 解析，文件读取与补丁写入继续校验项目目录边界和符号链接，Bash 的工作目录必须位于项目内，但不提供进程级沙箱隔离。

`storage` 管理项目配置文件、SQLite 会话元数据和历史日志文件读写；日志存储只定位文件并读写完整行，不解释会话事件或载荷。JSONL 事件的编码、解码和事件类型分派由 `service/session` 负责，Event 定义与内存状态推进规则属于 `core/session`。`Store` 在关闭时释放数据库连接；会话元数据仓储通过原子 SQL 更新，不额外加仓储锁。手动改名和自动命名由业务层发起，统一携带读取到的原标题进行原子条件更新；原标题不匹配时返回冲突，不自动重试，且不修改标题或时间戳。自动标题在业务层生成，仅在读取到空标题时尝试写入，已有标题时直接跳过。`core/session.Session` 使用数据锁取得快照或接纳 Entry、执行记录、用量和耗时，使用独立的同步提交锁保证接纳与日志追加顺序，不在持有数据锁时等待存储；Run 自身不设置更新锁，展示查询只读取 Session 发布的记录值。历史写入失败保留内存更新，重复 Entry 不重复写入。分支结构先提交 SQLite，成功后才接纳到内存，不通过历史日志创建分支。`service/session` 负责索引推进、定点解码、恢复决策、实例登记及配置管理。配置锁只保护快照与整体替换，候选构建在锁外。Coordinator 按 SessionID 串行化生命周期、分支结构与队列交接，命令锁不覆盖模型和工具执行；锁登记包含持有者和等待者，全部退出后回收。共享注册表锁只保护定位、登记、移除及定位快照，不在其内部等待队列锁、会话数据锁、磁盘、Hook 或执行退出。数据锁只保护修改和快照，排序及展示计算在锁外。不同会话独立加载、执行和释放。

Entry 通过 ID 和 `ParentID` 组成历史树，完整记录保存在实际所属分支的日志中。分支持有独立 Head，共享祖先不复制、不改变归属；从继承历史分叉时，父分支取分叉节点的实际所属分支，而不是当前浏览分支。新分支先建立独立目录与空日志，再事务提交结构和默认选择，初始 Head 等于分叉点；提交失败清理本次未登记目录，恢复不扫描或收养遗留分支目录。

根分支不可删除，有子分支时拒绝删除，不隐式级联。删除在执行及队列交接结束后发起，以 SQLite 事务为逻辑提交点，同时移除所属节点、Run、Turn、工具关联和索引进度。删除当前分支时，剩余分支按 UpdatedAt 降序、BranchID 升序选择，默认选择与删除同事务更新；删除非当前分支不改变选择。提交后释放绑定与页面结果，再清理整个分支目录；不读被删除分支正文，不重写其他日志。物理清理失败返回明确结果，可定点重复清理，分支不复活。切换分支释放旧正文及浏览状态，再次进入重新请求；工作区标签切换则保留会话页。

运行期在首次接纳 Entry 和模型请求收尾时增量更新统计，普通 Run 更新不扫描已有 Entry；只在执行准入或必要恢复时重建条目统计。Run 完成模型、工具和子执行后，将终态、展示统计、累计用量及稳定身份的 Run Entry 放入同一次历史提交。结束节点不进入模型上下文，同一 Run 重复结算不创建第二个节点；主、子 Run 各自保存累计值，不将子 Run 再次计入父 Run。主会话结束节点允许分叉，子代理结束节点不作为主分支分叉点。历史查询先批量取得目标路径的轻量节点，再读取本页正文；模型上下文只展开最后摘要、摘要保留的原文及之后的模型可见记录，不受界面页大小限制。恢复回执的引用顺序在实际上下文范围内整理，不改变原始 Entry、ParentID 或日志顺序。Run 只持有本次执行实际接纳的 Entry，不持有整条分支历史。普通、摘要和风险审核请求各有独立 TurnID，以 Run 内请求序号生成；开始与收尾更新同一请求记录，失败或取消仍保存已取得用量，未上报分项保持未知。会话累计按唯一 Run 的最新值求和，不重复计入共享祖先或子 Run；Turn 明细与 Run 累计不相加。

完整业务记录生成后先更新内存，再立即追加一行 JSONL；不逐 token 写日志，不在每条记录、执行结束或退出时额外 fsync，磁盘刷写交给操作系统，不承诺断电持久化。编码、取消和写入错误均向调用方返回，不回滚内存，也不封锁会话；关闭会话时释放内存实例，未成功写入的内存记录可能随实例释放或进程退出而丢失。同一 Entry 的重复提交不会自动补写日志。追加 I/O 失败可能已经产生部分写入，不能据此认定操作可安全重试。执行终态已在内存接纳时，保存失败只报告错误并正常释放执行占用，不反复重试结算。不支持运行期间从外部修改文件。日志层读取时只交付完整行，不完整尾行先备份再截断；业务重放遇到完整坏行明确报错。

创建会话先建立根分支空日志，再事务提交 SQLite 会话、分支结构与默认选择；提交失败尽力清理本次建立的空目录。创建与删除统一由 Coordinator 接纳并计入关闭等待；创建的存储操作不持有调度锁，创建登记复用注册表锁保护。非空的新会话在正常释放实例时退出空会话清理登记，避免退出时把已释放的历史误判为空。应用退出先拒绝新命令，等待已接纳命令与执行全部退出，再单线程清理本进程新建的空会话并释放实例，最后关闭存储。删除由 Coordinator 确认没有活动执行后进行，以 SQLite 删除为提交点：数据库删除失败直接返回错误，不触碰 JSONL；数据库删除成功后释放写入绑定、会话内存和分支请求缓存，并尽力删除 JSONL，清理失败允许留下孤儿文件，不回滚数据库删除。会话目录只由 SQLite 查询，不扫描、收养或重放未被引用的 JSONL。

节点预览、正文行位置、Run 展示、Turn 明细、工具关联及日志连续索引进度是 SQLite 派生数据，每行的投影更新与进度推进在同一事务提交。首次建立索引只扫描 SQLite 登记的存活分支，之后从进度继续读取，不收养遗留分支目录。日志已完整追加而索引失败时保留日志，从既有进度补齐，不重复提交业务记录；补齐失败明确返回错误。恢复根据执行及工具关联投影定位候选，只读取这些 Run 的实际记录，为缺失回执补写 `tool_interrupted`，先结束子执行再发布父执行结束节点。已保存终态但尚无完整结束节点的 Run 同样完成收尾，不改写发布后的 Entry，也不创建第二个结束节点。恢复不请求模型、不执行工具、不恢复审批或进程内队列。普通正文读取只读完整定位记录，不执行尾行备份或截断。

会话历史只接受匹配版本的单 Event 结构，无法识别的完整日志行明确报错，不自动迁移真实历史。派生历史索引可以从存活日志重建，但分支存在性、父关系和默认选择只能由 SQLite 业务元数据恢复；不能把整个数据库视为可从 JSONL 重建。运行前备份数据库与对应日志，回滚时一并恢复匹配的程序、数据库和日志。
